01

What SAS is & why use it

SAS stands for Statistical Analysis System. It's an all-in-one environment for working with data at scale: data manipulation, statistical modeling, reporting, visualization, and machine learning / AI. That breadth makes it a staple tool for data analysts, data scientists, statisticians, and BI analysts.

Unlike R and Python, which are free and open source, SAS is a licensed, tightly regulated platform with strong security and validation guarantees baked in. That's exactly why it stays entrenched in industries where being auditable matters — government, healthcare, pharmaceuticals, finance, and insurance — and why it shines on very large data sets it can crunch with little processing overhead.

Free start

You don't need a paid license to learn. SAS OnDemand for Academics is a free, browser-based version with sample data sets built in (see topic 06). Everything in this guide runs there.

02

Syntax & comments

SAS code is a series of statements, and every statement ends with a ; semicolon. Count the semicolons and you've counted the statements. A few forgiving rules make SAS easy to start with:

Case

Not case-sensitive

Variable names ignore case — Sex, SEX, and sex all refer to the same variable.

Whitespace

Indentation optional

Indents don't affect whether code runs (unlike Python) — but they make code far easier to read, so use them.

Missing ;

The #1 error

A forgotten semicolon causes most syntax errors. When something breaks, check your semicolons first.

Two kinds of comments

Commenting is strongly encouraged so teammates (and future you) can follow what a program does. SAS renders comments in green. There are two forms:

Comment styles
* Inline comment — starts with a star, ends with a semicolon;

/* Block comment — stars on the inside, slashes outside.
   Good for large explanations, and it CAN contain a ; safely. */
Why it matters

An inline comment ends at the first semicolon, so it can't contain one. A block comment can hold semicolons and multiple lines — use it for long explanations.

Data sets, variables & observations

SAS works with SAS data sets. Any other format (CSV, Excel, text) can be imported into one. A data set is a grid: variables are the columns, and observations (also called data points, or rows) are the records.

Name (char)Sex (char)Age (num)
AlfredM14
AliceF13
 F15
WillM.

Notice the alignment — it tells you the variable type at a glance.

Two variable types

left-justified

Character

Letters or numbers treated as text. Always aligned to the left of the column.

right-justified

Numeric

Numbers only (may include + − . e). Always aligned to the right.

Missing values

Real-world data is full of gaps. SAS marks them differently by type: a character missing value shows as a blank, and a numeric missing value shows as a period . (see Name row 3 and Age row 4 above).

Naming variables

SAS is picky about names. A valid variable name:

length

≤ 32 characters

Names longer than 32 characters are rejected.

first char

Letter or _

Must start with a letter or underscore — never a number.

allowed

Letters, digits, _

No special characters except the underscore. So _id and age2 are fine; age! is not.

04

DATA steps vs PROC steps

Every SAS program is built from two kinds of steps, each made of statements. Knowing which step you're in tells you which statements are legal.

keyword: data

The DATA step

Creates and modifies data sets — cleaning, filtering/subsetting, creating new variables, merging, replacing missing values.

keyword: proc

The PROC step

Runs a ready-made procedure: analyzing, sorting, summarizing, printing reports (e.g. PROC MEANS, PROC SORT).

Match statement to step

Some statements belong to only one step. A SET statement, for example, works in a DATA step but not in a PROC step. Using the wrong one is a common error.

How a DATA step runs, and how to end it

A DATA step executes line by line, observation by observation: it reads the first observation, runs through every line, writes it out, then reads the second observation and repeats. End a step with RUN; (or QUIT; for some procedures) — a step also ends when SAS hits the next DATA or PROC step.

05

The SAS log

Alongside your Code, Results, and Output Data, the Log is where SAS tells you what happened: the SAS version, data set names, the number of observations and variables, line numbers, resources used, and any errors, warnings, or notes. When there's a syntax error, the log underlines the offending line.

Always read the log

Even when code runs with no red error, check the log — did you lose data? If you started with 19 observations and expected a filter to leave 9, the log confirms it. An accidental drop to a fraction of your rows is caught here, not in the output.

Writing your own notes with PUT

The PUT statement writes a message to the log — handy inside a condition to trace how many rows matched.

Filter to females, and log each match
data class_report;
   set sashelp.class;
   if sex = 'F' then put 'Female observation';  * writes to the log;
run;

Run this and the log prints "Female observation" once per matching row — and reports the observation count dropping from 19 to 9, confirming the filter did what you expected.

06

Libraries & importing data

SAS organizes data sets into libraries — think of a data set as a book and a library as the shelf it lives on. Three libraries exist by default:

WORK

Temporary

Scratch space. Everything here disappears when you log off.

SASHELP

Sample data

Practice data sets like class, cars, baseball, air.

SASUSER

Your saved sets

A place provided to you for saving your own data sets.

One-level vs two-level names

A name's number of parts decides where it's stored. A one-level name like class_report (no dot) goes to temporary WORK. A two-level name like sashelp.class points to a permanent library and data set.

Making your own permanent library

The LIBNAME statement assigns a nickname to a folder so you can read from and write to it permanently.

Assign a library, then save into it
libname mydata "/home/u123/class_datasets";   * nickname → folder path;

data mydata.class_report;   * two-level name = permanent;
   set sashelp.class;
run;
Library naming rules

A library name (the libref) must be ≤ 8 characters, start with a letter or underscore, and contain only letters, numbers, and underscores.

Importing files

In SAS OnDemand, upload a file, right-click it, and choose Import Data — SAS generates a PROC IMPORT for you. On a licensed desktop install, write it yourself:

PROC IMPORT (desktop)
proc import datafile="C:\data\magnolia.xlsx"
   out=sasfiles.magnolia
   dbms=xlsx replace;
run;
Tip

Keep throwaway, exploratory data in WORK — only save to a permanent library when it's close to a final copy or something you'll revisit. It saves disk space and processing time.

07

The DATA step in depth

The DATA step is where data is built and reshaped. You can create a data set from an existing one, from raw data (a text/CSV file), or from data typed directly into the editor; subset it, create variables, merge sets, and clean missing values.

From an existing data set: DATA + SET

DATA names the data set you're creating; SET names the existing one you're reading from.

Create a new set from an existing one
data class_report;      * create (one-level → WORK);
   set sashelp.class;    * read existing (two-level → permanent);
run;

From raw data typed in: DATALINES + INPUT

Great for practice or a few test rows (not thousands). INPUT names the variables and their types — a $ after a name means character; no dollar sign means numeric.

Type raw data directly into SAS
data test_set;
   input name $ height weight;   * name is character;
   datalines;
Ben 154 88
Ann 160 55
Pablo 172 90
;
run;
SET vs INPUT

Never use INPUT with SET. A SET reads an existing SAS data set, which already knows its variable names. Use INPUT only with DATALINES (typed data) or with INFILE (reading an external text/CSV file).

Messy files: column pointers

For unstructured files with misaligned fields, tell SAS the exact columns each variable spans, e.g. input name $ 1-6 height 7-9 weight 11-13;.

08

Conditional logic

IF / THEN statements subset data and create variables based on conditions — the same idea you'll see in Python and R. Use ELSE IF when there are more than two levels to test.

IF / ELSE IF / ELSE — bucket a numeric variable
data cars_cyl;
   length car_size $ 20;              * size the new char var first;
   set sashelp.cars;
   if cylinders = 4 then car_size = 'small';
   else if cylinders = 6 then car_size = 'medium';
   else car_size = 'large';
run;

Two actions at once: IF / THEN / DO

When a single condition should trigger more than one action, wrap them in a DO ... END block. Every action gets its own semicolon, and the block must close with END;.

One condition, several assignments
if cylinders = 4 then do;
   car_size   = 'small';
   popularity = 'high demand';
end;
Watch for

An "unclosed DO block" error means you forgot the END; — or the semicolon after then do.

09

Informats & formats

SAS can't read non-standard data — values with special characters like $, %, -, or / — without help. An informat tells SAS how to read a value in. (This only applies to raw/typed data or non-SAS files; SAS data sets already know their formats.)

$w.

Character

Has a dollar sign, e.g. $6. reads up to 6 text characters.

w.d

Numeric

No dollar sign; the optional .d is decimal places.

mmddyy10.

Date

Reads dates like 01/15/2024 — among the most-used informats.

Informat vs format — not the same thing

An informat reads a value in; a format controls how it's displayed out. SAS stores dates as integers (Jan 1, 1960 = day 1), so after reading a date you apply a format to make it human-readable.

Read a date in, then display it as a date
data sales;
   format date mmddyy10.;                * display it as a date;
   input price dollar6. region $ date mmddyy10.;
   datalines;
$54.20 West 01/15/2024
;
run;
10

Functions

Functions transform values — there are character, date/time, math, financial, and statistical families (and more). SAS colors functions in blue. A few you'll reach for constantly:

Rounding & date parts

CEIL to round up; MONTH / YEAR to split a date
data customer_trends1;
   set customer_trends;
   rounded_price = ceil(price);   * round up to next whole number;
   month = month(date);          * pull month into its own column;
   year  = year(date);           * ...and year, for annual analysis;
run;

Related rounding functions: round() (nearest) and floor() (round down).

Joining text: concatenation with CATX

CATX combines character variables and lets you set the separator as its first argument. Note the commas — commas are rare in SAS outside function calls.

Combine make + model into one field
data make_model;
   set sashelp.cars;
   make_model = catx(' ', make, model);   * separated by a space;
run;
11

Essential procedures

Procedures (PROC steps) do the analysis and reporting. Every one follows the same shape: proc <name> data=<dataset>; then options, then run;. Five carry most beginner workflows.

PROC CONTENTS — explore before you program

Shows a data set's structure: variable names, types, lengths, how many observations and variables, when it was created, and any sort order. Always look before you leap.

PROC CONTENTS
proc contents data=sashelp.cars;
run;

PROC SORT — order the rows

Sorts a data set. You usually output to a new (WORK) set because SASHELP data can't be overwritten. Sorting is a prerequisite for using a BY statement in PROC PRINT.

PROC SORT
proc sort data=sashelp.cars out=cars;
   by type;
run;

PROC PRINT — report the data

Prints selected variables, optionally grouped and summed, with titles and footnotes. To group with BY, the data must already be sorted by that variable.

PROC PRINT with BY, SUM, title & footnote
title 'Total Invoices by Type';
footnote 'Auto Analyst Department';
proc print data=cars;
   by type;
   var type make model invoice;
   sum invoice;
run;

PROC FORMAT — relabel & bin values

Defines reusable formats — turn M/F into Male/Female, or bin ages into groups — then apply them. Cleaner than writing IF statements across many data sets. A $ prefix marks a character format; format names are ≤ 8 characters.

PROC FORMAT, then apply on the way out
proc format;
   value $gender 'M'='Male' 'F'='Female';
   value agelvl  11-12='Preteen' 13-high='Teen';
run;

proc print data=sashelp.class;
   format sex $gender. age agelvl.;   * dot always follows a format;
run;

PROC MEANS — summary statistics

The go-to for quick stats: mean, median, standard deviation, min, max, N, missing counts. CLASS groups the stats, VAR picks the variable, and maxdec= limits decimals.

PROC MEANS by group
proc means data=sashelp.baseball mean median std max min maxdec=2;
   class division;
   var nhits;
run;
12

Exporting data

The mirror image of importing. In SAS OnDemand, right-click a data set → Export → save to your files → download. On a licensed install, use PROC EXPORT, naming the source set, the destination file, and the format (DBMS).

PROC EXPORT
proc export data=work.hotels
   outfile="/home/u123/hotels.csv"
   dbms=csv replace;
run;
